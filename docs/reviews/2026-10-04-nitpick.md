## 总评

**6.0/10**

成熟度高的 monorepo(M39 已 ship,1502 pytest 通过,成熟 OTel / CORS / Sandbox 加固),但 **3 个真实的 P0 安全洞** 加 **1 个隐性架构债(sync DB in async route)** 加 **无 CI** 让整体风险指数远超"6/10"对应的分值。最紧迫的是补默认 value 守护、给 electron_ws 端点加 auth、补一周 P1 安全接入。

## 系统性问题

### 系统性 1:`@root:tactical-mode` — 默认值无启动 guard

- **根因**:`lumen_core/config.py` 用 `field: str = "default"` 这种 pydantic-settings 默认值,但只在 `EXTERNAL_JWT_SECRET` 一个 key 上加了启动期拒绝(`lumen_main.py:269-283`)。`SECRET_KEY` / `WX_PUBLISHER_FERNET_KEY` 等其他敏感 key 用同样模式但**没同等检查**,形成了不一致的 secret hygiene 风格。
- **影响维度**:安全(C1/C2)、DX(F5 启动期 crash vs 线上 silently 用弱 key)、测试(无 boot test 覆盖这条 guard 路径)。
- **级联修复**:`lumen_core/config.py:settings` 的 `model_validator` 一行扫所有 `_*SECRET*` / `*_KEY*` / `*_TOKEN*` 字段,默认 placeholder 出现就 refuse-to-boot,跟现有 `EXTERNAL_JWT_SECRET` 模式对齐;同时为每条 guard 写一个 boot test。

### 系统性 2:`@root:no-ci` — 所有"质量门"形同虚设

- **根因**:无 `.github/workflows/`(已确认),CLAUDE.md 列的 `pytest` / `mypy` / `tsc` 命令只在 `pre-commit-config.yaml` 走 dev 端 hook,**没有任何远端 CI 强制**。意味着:
  - 1502 pytest 是 dev 机结果,不保证 main 分支绿
  - `pytest.ini` `mypy` `eslint` 不一致配置无统一调节
  - security 漏洞(secret 默认值 / electron_ws 无 auth)一旦 ship 到 main,merge 前没拦
- **影响维度**:DX(F4)、安全(S4 依赖审计)、测试(T1 shape 无人 enforce)、代码质量(注释要求 lint 不过的代码无法被自动拦)。
- **级联修复**:加 `.github/workflows/ci.yml` 跑 `ruff check` + `mypy` + `pytest` + `tsc --noEmit` + `vitest` + `pip-audit` + `npm audit --omit=dev`;**必修必修必修**,30 行 yaml。

### 系统性 3:`@root:fat-controllers` — Service / Controller 边界不清

- **根因**:5 个核心 router(`chat.py` / `workflow.py` / `knowledge.py` / `skill_market.py` / `electron_ws.py`)同时做 ORM + 业务逻辑 + response shaping。`/chat/stream` 单 endpoint 内 7+ 关注点。
- **影响维度**:架构(A2/A6)、性能(D3 chat 5 次串行 DB)、测试(E1 单测只能 mock 私有 helper)、DX(F5 新人 review 单 endpoint 要看 5+ 文件)。
- **级联修复**:立"Controller 只能做 HTTP+DTO"立规矩(CA-lite);`/chat/stream` 抽到 `ChatService.stream_message()`;补 service 单测(E1 一次性补齐 24 个);未来 router 改用 `Depends` 注入 service。

### 系统性 4:`@root:no-types` (Python 端) — `Dict[str, Any]` leak 多发

- **根因**:`SingleResponse[Dict[str, Any]]` 在 5+ endpoint 里直接返,前端 `res.data.data` 拿到 untyped dict 后 TS 端反复 `as any` 强转(B9/P8 + P3)。
- **影响维度**:代码质量(B2/P1、B9/P3)、测试(E3 assertion 难做)、DX(F5 新人 review 难)。
- **级联修复**:为 `Dict[str, Any]` endpoint 补 Pydantic schema;前端对应 schema 跟后端 codegen(用 `openapi-typescript`);一次 ship 5 个 endpoint。

### 系统性 5:Repo hygiene 累积 drift

- **根因**:`backend;C/` 路径 artifact + `uvicorn_restart.log` 41KB + `backend/openapi.json` 538KB + BM25 `.pkl` + `lumen_schema_2026-09-02.sql` 112KB — 多个"应该 ignore 但没 ignore"的文件被 force-added 进 git。
- **影响维度**:DX(F9 `.gitignore` 不可信)、测试(无用 artifact 拖大 git clone)。
- **级联修复**:加 `.gitignore` `backend/data/faiss/*.pkl`、`/*.log`(root 级别)、`backend/openapi.json`;`git rm --cached` 这几个文件;**一次 ship**。

## 关键观察(项目级)

1. **纪律强 / 风险点集中**:CORS / OTel / Logging / Sandbox / rate-limit 这些容易翻车的子系统都被认真加固(参见 `dynamic_cors.py` / `otel.py` / `sandbox/runner.py`),但 P0 集中在 3 处:**SECRET_KEY 默认值无守门** / **electron_ws 4 端点无 auth** / **`/chat/stream` 是胖 controller + sync DB**。
2. **模式重复度高但仍未抽抽象**:26 个 service 缺 test(E1),说明服务模块化做得好,但测试习惯没贯彻;5 个 service router 都做 ORM + 业务判断 + response shaping → 缺一个明确的"Controller 只能做 HTTP+DTO,业务全在 Service"强制规范。
3. **同步 DB in async route 是最大隐形债**(D1):仅 4 处用 `asyncio.to_thread`,205 个 async endpoint 全用 sync SQLAlchemy session。FastAPI 在并发请求下 event loop 被频繁 block — chat/stream 高并发时 `uvicorn --workers 1` 必然打不满 CPU。
4. **测试覆盖率假象**:1502 passed 数字很漂亮,但 24 个 service 缺测试 + 多文件 < 5 asserts + 1 个 0-asserts 测试 → 覆盖率可信度打折。
5. **CLAUDE.md 已 ship 大量 Phase 0/1 鲁棒性工作**(M36 视频合成 / M37 RAG 评测 / M38 storage / M39 multi-agent),但 P0 安全债一直累积 — Phase 2 应该包含本次 audit 列的 P0/P1 修复,优先级比 Phase 1 后续更靠前。
